# Voice / Pipecat deps — install into the SAME backend/.venv:
#   .\.venv\Scripts\pip install -r requirements-voice.txt
#
# Kept separate from requirements.txt so CRM API upgrades are not coupled to
# Pipecat's transitive graph (onnxruntime, aiortc, av, silero).
#
# Flows ships inside pipecat-ai>=1.5 (`from pipecat.flows import FlowManager`).
# Do NOT install the deprecated standalone `pipecat-ai-flows` package — it pins
# an older pipecat and breaks imports.
#
# Pinned, not floating: an unpinned `>=` means a Pipecat release can change the
# voice runtime inside an image rebuild with no code change and no review.
# Bump these deliberately, then re-run backend/scripts/run_voice_evals.py.
# `deepgram` is here because the provider registry offers Deepgram STT for
# binding. Without the extra the service class does not import, so binding it
# fell back to Azure — the studio offering a provider the runtime cannot run.
# Cartesia, ElevenLabs, Groq and Gladia need no extra: their Pipecat services
# are plain HTTP/websocket clients with no vendor SDK behind them.
#
# `speechmatics` is deliberately NOT here. It pulls transformers + huggingface
# _hub + tokenizers + safetensors — roughly a gigabyte of ML runtime — for the
# bilingual ar/en recogniser. Add it when that model is actually being bound;
# until then /providers/models reports it `runtime: unavailable` with the
# reason, which is honest and costs nothing.
pipecat-ai[azure,webrtc,runner,silero,deepgram]==1.6.0
# Used directly by voice/recording.py for stereo PCM interleave (also a pipecat
# transitive dep, but declared here so the import doesn't rely on that).
numpy==2.4.6

# Cross-encoder reranking (agent_core/tools/kb_rerank.py), off by default behind
# KB_RERANK_ENABLED. Pulls no torch: it runs on the onnxruntime that Pipecat's
# Silero VAD already brings in, so the marginal cost is the tokenizer plus the
# ~80MB model file. Pinned even though the feature is disabled, because without
# it the module cannot be measured inside the container -- which is the only
# place its latency budget can honestly be decided.
fastembed==0.8.0
