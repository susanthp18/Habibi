## What changed

**Backend — one computation, one shape**
- `backend/db.py`: `_sla_label()` (hour-rounded, no tone) is gone, replaced by `_dispute_sla(sla_due_at, captured_at, status) → (sla, slaLabel, slaMinutes)`, mirroring `_work_item_sla`'s tuple shape. Thresholds are the TS ones: past-due → `breach`, under 25% of the filing→due window → `warn`, else `ok`; closed → `done`/`"Closed"`. Label format is the board's: `0h 29m left` / `0h 40m over`.
- Both serializers now emit the fields: `_dispute_contracts` (Customer 360, also feeds POST/PATCH responses via `_dispute_by_id`) and `list_disputes` (board).
- `_sla_label` had exactly one caller (`db.py:1382`) — migrated, then deleted. Nothing else referenced it.
- `backend/schemas.py`: added `sla`/`slaLabel`/`slaMinutes` to `DisputeResponse` and `DisputeListResponse`. Not optional housekeeping — `DisputeListResponse` is `extra="forbid"`, so the new keys would have been rejected at the route.
- No schema change, so no migration/`sql/*.sql` edit is in play.

**Frontend — the client stops computing it**
- `slaInfo()` and `SlaInfo` deleted. `DisputeCard`, `DisputeSheet`, `DisputeBoard` (sort), `filterDisputes`, `computeMetrics` all read `d.sla` / `d.slaLabel` / `d.slaMinutes`.
- `DisputesTab` renders the server label and now colours it from the server tone — it could previously never show red.
- Mock: `fetchDisputes` maps seed rows through `withMockSla` on every fetch; the 360 seed rows and `createDispute`'s mock row produce the same three fields from the same rule.

**One file outside your scope list**: `Habibi/src/data/dispute-sla.ts`, holding `SlaTone`/`DisputeSla` and the mock's mirror of `_dispute_sla`. `disputes-seed` already imports `customer360-seed`, so putting the shared mock helper in either seed creates a real ESM cycle (TDZ crash at module init). `SlaTone` is re-exported from `disputes-seed`, so `SlaChip` is unchanged.
