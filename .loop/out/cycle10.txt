## Area map

**`backend/voice/` (39 modules, ~16.4k LOC)** — the Pipecat voice service. `voice/bot.py` builds the pipeline; `voice/host.py` mounts SmallWebRTC signalling into FastAPI (`main.py:611 register_routes`) or runs standalone on :7860; `main.py:3690` proxies Twilio `/ws` through `voice/ws_proxy.py`. `voice/persist.py` + `voice/crm_sink.py` are the DB edge (raw SQL on `db.engine`, ~30 call sites); `voice/tools.py` wraps `agent_core.tools.domain` for the flow; `voice/flows.py` / `flows_dynamic.py` build the hardcoded vs. Prompt-Studio graphs; `voice/twilio_ops.py` is called from `main.py` (6×), `outbound.py:511`, `agent_core/live_qa/enact.py:60`. `worker.py:265` only touches `voice.memory.purge_stale`. `voice/workers/insurance.py` is a separate compose service (`docker-compose.yml:239`).

**`backend/agent_core/skills/`** — progressive-disclosure skill packs. `main.py:2088-2254` exposes 14 `/agent-studio/skills*` routes over `skills/persist.py`; `worker.py:304` runs the nightly gardener; `skills/runtime.mouth_turn_state` is the per-turn entry point from `bot_runtime.py:898`, `sandbox_runtime.py:89/440`, `voice/bot.py:96/1059`; `db.py` (3 sites) syncs attachments.

**`backend/agent_core/connectors/`** — MCP connector registry. Six `/connectors*` routes in `main.py:2280-2318`; `dispatch()` is reached from `bot_tools.py:799` for `ext.*` tools and `bound_tool_names()` from `skills/intersect.py:104` at card-compile time.

## Findings

**1. `backend/voice/bot.py:1815` | P1 | CRM persistence failure is swallowed and the call proceeds with no interaction row, so the entire call is unrecorded** — `logger.exception("Failed to start CRM persistence — call continues without DB")` wraps the whole `bind_session_start` + `sink.start()` block (1727-1814). `session.interaction_id` stays `None`. Fix: on bind failure either abort the leg or set a degraded flag that forces `end_call` after the disclosure, rather than serving a full unlogged collections call.

**2. `backend/voice/crm_sink.py:1241` | P1 | Every queued CRM job is discarded with zero logging when `interaction_id` is unset** — `if not ix:` / `return` in `_handle_sync`, with the same guard at `:585` and `:653`. Downstream of finding 1 this drops transcript turns, tool-call audit rows, live alerts and guardrail violations silently. Fix: emit one rate-limited `logger.error` counting dropped jobs per session so the loss is visible in ops.

**3. `backend/agent_core/connectors/persist.py:252` | P1 | Operator-supplied connector URL is POSTed with no SSRF guard, reimplementing outbound HTTP that `webhooks_dispatch.py` already hardens** — `resp = httpx.post(str(conn["url"]).rstrip("/") + "/mcp", ...)`; the only validation is `_https_ok` (`:22`), which checks scheme/netloc but not the resolved address, while `webhooks_dispatch.resolve_public_host` / `_is_private_ip` (`:117`, `:132`) exist for exactly this. `https://169.254.169.254/mcp` passes. Fix: route both `_call_remote` and `_remote_tools_list` through `webhooks_dispatch.resolve_public_host`.

**4. `backend/bot_tools.py:174` | P2 | `get_customer_context` calls the paylink connector directly, bypassing approval status, allow-prefixes and the circuit breaker** — `pay = paylink_status(ctx.customer_id)`, gated only on `mcp_client_enabled()`, whereas the sanctioned path (`:799 dispatch(...)`) enforces `conn["status"] != "approved"` and `circuit.allow`. A draft or disabled connector still leaks payment data into every context read. Fix: call `connectors.persist.dispatch("ext.paylink.get_status", ...)` here instead of the module function.

**5. `backend/agent_core/connectors/persist.py:95` | P2 | Default connector id is not tenant-scoped, so the second tenant to create a given slug gets a primary-key violation** — `cid = str(payload.get("id") or f"conn-{slug}")` against `id TEXT PRIMARY KEY` (`sql/16_mcp_phase3.sql:38`), while the `ON CONFLICT (tenant_id, slug)` clause (`:107`) cannot absorb a PK conflict. `POST /connectors {"slug":"paylink"}` from tenant B 500s. Fix: default to `f"conn-{db._tenant()}-{slug}"` (or a uuid) and add `ON CONFLICT (id)`.

**6. `backend/agent_core/skills/runtime.py:71` | P2 | A DB failure loading signed skill packs falls back to on-disk platform defaults with no log, silently restoring tool grants the tenant edited away** — `except Exception:` / `pass` around `packs_for_slugs(slugs)`, then `pack_for_slug(slug)` from disk at `:76`. Because `intersect.effective_tools` gates writes on pack contents, this can re-grant `create_promise_to_pay` for a tenant whose signed pack removed it. Fix: log the exception and fail closed (return `[]`) so the gated-write filter denies rather than reverts to defaults.

**7. `backend/agent_core/skills/lint.py:13` | P2 | The skill linter is dead code — nothing calls `lint_pack`, so skills created via the API are never validated** — `def lint_pack(pack: SkillPack, *, catalog_names: set[str]) -> list[dict[str, Any]]:`; only the sibling constant `CATALOG_PREFIX_TOKEN_CAP` is imported (`agent_core/cards/compile.py:39`). `POST /agent-studio/skills` and `upsert_skill_from_pack` accept unknown/malformed `allowed-tools` and over-cap descriptions. Fix: call `lint_pack` in `skills/persist.create_draft_skill` / `upsert_skill_from_pack` and reject on `unknown_tools` / `malformed_tool_name`.

**8. `backend/bot_tools.py:799` | P2 | Connector dispatch discards the model's tool arguments** — `result = dispatch(name, customer_id=ctx.customer_id)`; `args` was just parsed and validated at `:784` but never forwarded, and `_call_remote` hardcodes `"arguments": {"customer_id": customer_id}` (`persist.py:259`). Any remote MCP tool taking a second parameter silently receives nothing. Fix: thread `args` through `dispatch` into the JSON-RPC `arguments` payload.

**9. `backend/agent_core/skills/sign.py:16` | P2 | Skill signatures verify against a hardcoded key when `SKILL_PLATFORM_KEY` is unset, so an unconfigured prod deploy trusts forgeable signatures** — `raw = (os.getenv("SKILL_PLATFORM_KEY") or "dev-skill-platform-key-not-for-prod").encode("utf-8")`. `verify_signature` (`:25`) is the G9 gate that lets a pack attach to a published card. Fix: raise on a missing key outside an explicit dev/test env rather than falling back.

**10. `backend/agent_core/skills/scripts.py:16` | P3 | Reimplemented contact-window logic has drifted from `db._outside_preferred_window`, so the same promise date gets two different verdicts** — `"""Same rule as db._outside_preferred_window — kept here so code-mode has no DB import."""`, but this copy defaults to `DEFAULT_WINDOW = "10:00-19:00 IST"` (`:11`, `:26`) while `db.py:1823` defaults to 9–20. A 09:30 IST promise with no `preferred_window` is in-window per `db.py` and out-of-window per `promise_date_in_window`. Fix: move the pure function into a DB-free module (e.g. `contact_policy`) and import it from both.

**11. `backend/agent_core/skills/intersect.py:108` | P3 | Connector tool binding is wrapped in a bare `except: pass`, so a DB blip silently strips every `ext.*` tool from a compiled card** — `except Exception:` / `pass` around `bound_tool_names(...)` at `:104-109`; the card compiles as if it had no connectors and the failure never reaches the compile issues list. Fix: log and surface it as a compile warning on the card.

**12. `backend/agent_core/connectors/persist.py:161` | P3 | `bound_tool_names` runs the same `SELECT * FROM mcp_connectors` twice per call, on the card-compile hot path** — `by_id = {c["id"]: c for c in list_connectors()}` immediately followed by `by_slug = {c["slug"]: c for c in list_connectors()}` at `:162`. Fix: bind `rows = list_connectors()` once and build both maps from it.

**13. `backend/agent_core/skills/persist.py:635` | P3 | A signed DB pack that fails to parse silently degrades to the unsigned on-disk pack for that slug** — `except Exception:` / `logger.exception("signed skill pack %s failed to parse", slug)` then falls through to `pack_for_slug(slug)` at `:636`, so a corrupt tenant skill is served as platform default content under the same slug. Fix: skip the slug entirely on parse failure so the gated-write filter denies instead of substituting.

**14. `backend/agent_core/connectors/first_party.py:22` | P3 | `paylink_status` reads `payment_intents` with no tenant predicate, unlike every other query in the subtree** — `with db.engine.connect() as conn:` … `WHERE pi.customer_id = :cid` (`:30`), while `list_connectors`/`get_connector` both carry `AND tenant_id = :t`. RLS is opt-in and `rls.py:18-23` notes the app connects as a BYPASSRLS role, so nothing else stops a cross-tenant `customer_id`. Fix: join `customers` and add `AND c.tenant_id = :t`.

**15. `backend/agent_core/connectors/circuit.py:16` | P4 | Zero test coverage for the connector circuit breaker, including the fail-closed-forever branch** — `def allow(connector: dict[str, Any]) -> bool:` with `except ValueError: return False` at `:23-24`; no test in `backend/tests/` references `connectors.circuit` (`test_mcp_phase3.py` covers only `strip_result` and `paylink_status`). A malformed `circuit_opened_at` string permanently blocks the connector with no recovery path. Fix: add tests for open/cooldown/reset and treat an unparseable timestamp as open-circuit-expired rather than permanently closed.
